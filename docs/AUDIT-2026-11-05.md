## Risks and follow-up items

1. Two `030_*.sql` files make naïve migration tooling ambiguous. Record both explicitly or rename only in a future migration-management change without altering applied history.
2. Root historical documents still contain stale details. They now defer to `docs/`, but a future cleanup should consolidate duplicate handoffs.
3. `AGENTS.md` is an instruction file and should remain aligned with current behavior; it currently contains older wording in places. Review it before the next feature change.
4. Some old root instructions mention credentials or historical database hosts. Treat them as historical and rotate any exposed credentials.
5. The repository has no automated migration ledger in `package.json`; production migration state must be tracked externally.
6. GitHub analysis has API pagination limits (100 branches/commits/PRs/reviews per request) and intentionally does not infer activity that GitHub does not expose.
7. The `activeKeyIndex` Groq rotation is process-local; serverless instances do not share quota state. Each request still fails over correctly within its own process.
8. Browser-extension body mutations can produce hydration warnings during local development.

## Audit conclusion

The codebase is transferable after securely moving environment values and confirming Supabase migration state. The canonical onboarding path is `docs/TRANSFER.md`; the canonical technical reference is the rest of this directory.
